# LingChat 场景及光影设置 V1 Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task. Every production change follows RED → GREEN → REFACTOR; do not batch all tests before implementation.

**Goal:** 在不破坏旧场景数据的前提下，为 LingChat 增加可搜索、可编辑、可导入导出、可被 AI 临时切换的静态立绘与场景光影系统，并使主窗口、投屏和剧本试玩使用同一套渲染语义。

**Architecture:** Rust 作为预设、资源包、运行时状态和 AI 工具的权威层；Vue/Pinia 只保存当前 WebView 的镜像。场景保存光影参数快照及来源元数据，临时光影只存在当前进程，绝不进入普通存档快照。所有场景/光影变化通过带单调 revision 的全量 `scene-state:changed` 事件同步，避免双事件乱序。渲染采用共享 TypeScript 样式编译器和共享 Vue 光效层组件，正式画面与编辑预览不再各自拼 CSS；`.linglight` 检查会话由 Tauri managed state 持有，不依赖局部 `TempDir`。

**Tech Stack:** Vue 3.5、TypeScript 5.6、Pinia 3、Vite 6、Vitest、Vue Test Utils、Tauri 2、Rust 2021、serde、zip 2、tempfile、image、infer。

## 2. 目标领域模型

### 2.1 场景快照

保留现有 `Scene.lighting` JSON 字段，扩展场景为：

```rust
pub struct Scene {
    // existing fields...
    pub lighting: Option<LightingParams>,
    #[serde(default)]
    pub lighting_preset_id: Option<String>,
    #[serde(default)]
    pub lighting_preset_revision: Option<u32>,
    #[serde(default)]
    pub lighting_customized: bool,
}
```

规则：

- `lighting` 是独立快照，渲染永远读取快照/运行时副本，而不是实时追踪预设。
- `lighting_preset_id`、`lighting_preset_revision` 只记录来源；预设被删后允许保留悬空来源，并在 UI 显示“基于 X，来源已删除”。
- 应用预设后参数未修改时 `lighting_customized=false`；用户手调任意渲染参数后设为 `true`，UI 显示“基于 X，已自定义”。
- “恢复当前预设值”仅在来源预设仍存在时可用；来源删除时禁用并解释原因，“恢复系统中性值”始终可用。
- Rust/TypeScript 的 `SceneInfo`、`CreateSceneRequest`、`UpdateSceneRequest`、`model_to_info` 和弹窗 submit payload 必须完整贯穿三个来源字段；不得只改 `Scene` 模型。
- 旧场景缺少这些字段时使用 `None/false`。

### 2.2 光影参数 V2

新建 `src-tauri/src/ai_service/game_system/lighting.rs`，将现有 `FilterParams`、`LightingParams` 从 `scene_store.rs` 迁入。序列化格式建议：

```rust
pub struct LightingParams {
    pub schema_version: u32,                 // V2 = 2
    pub enabled: bool,
    pub master_intensity: f64,               // 0.0..=2.0
    pub link_character_background: bool,
    pub character: FilterParams,             // 旧色彩校正继续兼容
    pub background: FilterParams,
    pub character_ambient: AmbientParams,
    pub background_ambient: AmbientParams,
    pub main_light: MainLightParams,
    pub rim_light: RimLightParams,
    pub bloom: BloomParams,
    pub vignette: VignetteParams,
    pub asset_layers: Vec<LightingAssetLayer>,
}
```

关键子类型：

```rust
pub enum LightShape { Radial, Linear }
pub enum LightingTarget { Character, Background, Both }
pub enum BlendMode { Normal, Screen, Add, Overlay, SoftLight, Multiply }
pub enum AssetPlacement { Behind, Front }
pub enum AssetFit { Cover, Contain, Stretch }

pub struct AmbientParams { enabled, color, opacity }
pub struct MainLightParams {
    enabled, shape, target, x, y, angle, radius,
    color_start, color_end, opacity, blend_mode
}
pub struct RimLightParams {
    enabled, color, intensity, width, softness, angle, offset
}
pub struct BloomParams { enabled, target, color, radius, intensity }
pub struct VignetteParams { enabled, color, intensity, radius, softness }
pub struct LightingAssetLayer {
    id, asset_hash, media_type, target, placement, z_index,
    opacity, blend_mode, fit, required
}
```

Wire 与默认值必须写死，不能依赖 `derive(Default)`：

| 字段                                | Wire/范围                     | 中性默认      |
| ----------------------------------- | ----------------------------- | ------------- |
| `schema_version`                    | `2`                           | `2`           |
| `master_intensity`                  | `0.0..=2.0`                   | `1.0`         |
| x/y/radius                          | 归一化 `0.0..=1.0`            | `0.5/0.5/0.8` |
| angle                               | `0.0..360.0`                  | `0.0`         |
| ambient/main/bloom/vignette opacity | `0.0..=1.0`                   | `0.0`         |
| rim intensity                       | `0.0..=2.0`                   | `0.0`         |
| rim width/softness/offset           | `0..=64px`                    | `0`           |
| bloom radius                        | `0..=64px`                    | `0`           |
| asset opacity                       | `0.0..=1.0`                   | `1.0`         |
| asset z-index                       | `0..=7`，只在固定 slot 内排序 | `0`           |

Rust serde 使用 `snake_case`；前端 DTO 适配集中在 API 层。混合模式 wire 到 CSS 的映射固定为：`normal→normal`、`screen→screen`、`add→plus-lighter`、`overlay→overlay`、`soft_light→soft-light`、`multiply→multiply`；若目标 WebView 不支持 `plus-lighter`，仅 `add` 降级到 `screen` 并产生一次告警。

兼容规则：

- 旧嵌套 `character/background + overlay_*` 映射到 V2 `main_light`。
- 更旧的顶层滤镜继续复制到 `character/background`。
- 所有新增字段 `serde(default)`。
- 未知枚举值回退安全默认值，不得导致整个 `scenes.json` 无法加载。
- `normalize()` 在 Rust 权威层钳制范围并规范颜色；前端校验只负责即时反馈。
- `master_intensity` 在样式编译时乘到效果强度，不改写各子参数。

```rust

```

- 内置预设使用稳定 ID：`builtin:neutral`、`builtin:cold-backlight`、`builtin:warm-side`、`builtin:moonlight`、`builtin:indoor-soft`。
- 内置预设由代码生成、不可覆盖或删除；名称/说明由前端 `i18n_key` 显示。
- 用户预设存于 `<data_dir>/game_data/lighting_presets.json`。
- 搜索索引包含显示名、别名、标签、说明；英文比较大小写不敏感，中文直接包含匹配。
- `LightingPresetStore` 必须作为 Tauri managed state，由进程级 async mutex 串行化 CRUD、收藏、最近使用及导入 commit；仅“原子 rename”不足以避免并发 lost update。

### 2.4 资源

- 内容寻址目录：`<data_dir>/game_data/lighting_assets/<sha256>.png`。
- 预设和场景快照均引用 `asset_hash`，不引用导入临时目录。
- 删除预设不删除资源，保证场景快照不失效；孤儿清理不在 V1。
- V1 单 PNG：不超过 4096×4096、不超过 20 MiB；每预设最多 8 层；整个包不超过 100 MiB。
- 对外 DTO 不把 hash 当作 URL。Rust 为已验证 hash 附加只读 `resolved_path`；前端仅对该受控路径调用 `convertFileSrc`。hash 非法、文件缺失或路径越界时返回结构化 warning；移动端直接忽略 asset layer。

### 2.5 运行时光影

在 Rust `GameStatus` 和前端 `GameState` 分别增加：

```text
active_lighting: LightingParams | null
active_lighting_preset_id: string | null
active_lighting_source: scene_default | manual | ai | neutral
lighting_revision: u64
```

- 临时状态不写入 Tauri Store，也不加入持久化 `GameStatusSnapshot`；应用重启或载入存档后由被恢复场景的默认光影重新计算。
- 剧本试玩使用独立的进程内 `PreviewRuntimeLightingBackup` 保存/还原上述运行时字段，禁止复用持久化存档快照承载临时光影。
- 无场景时使用中性光影，仍可临时作用于角色。
- 场景切换：原子更新场景、背景、当前光影并递增 `lighting_revision`，只广播一个全量 `scene-state:changed` 事件；前端丢弃 revision 小于当前值的乱序事件。
- 保存当前场景：写入当前参数快照与来源 ID；如果是当前场景，立即刷新所有窗口。
- `WebInitData`、`game-info.ts`、cast snapshot/mirror 均携带完整运行时光影与 revision。WebView 重载保留进程内临时光影；应用进程重启不保留。
- 启动恢复不得在用户明确保存了“无场景”后随机选择场景；为 `LAST_SCENE_ID` 区分“从未设置”和“明确为空”。

状态转换表：

| 操作                    | 当前临时 manual/AI | 结果                                                         |
| ----------------------- | ------------------ | ------------------------------------------------------------ |
| 切换场景                | 任意               | 载入新场景快照；无快照则中性；source=`scene_default/neutral` |
| 保存当前场景新默认光影  | 任意               | 立即应用新快照；source=`scene_default`                       |
| 仅修改当前场景名称/描述 | manual/AI          | 保留临时光影                                                 |
| 删除当前场景            | 任意               | 场景为空并应用中性                                           |
| 删除当前来源预设        | manual/AI          | 保留运行时快照，标记来源已删除                               |
| 保存活动光影为场景默认  | manual/AI          | 写快照后 source=`scene_default`                              |
| 切换角色/清空对话       | manual/AI          | 保留临时光影                                                 |
| 加载普通存档/应用重启   | 任意               | 不恢复临时光影；按存档场景快照重新计算                       |

## 3. `.linglight` V1 格式

`.linglight` 是 ZIP，最小结构：

```text
preset.linglight
├─ manifest.json
└─ assets/
   └─ <sha256>.png
```

`manifest.json`：

```json
{
  "format": "linglight",
  "version": 1,
  "originId": "optional-origin-id",
  "revision": 1,
  "metadata": {
    "name": "冷色逆光",
    "description": "...",
    "aliases": ["cold backlight"],
    "tags": ["冷色", "逆光"],
    "category": "cinematic"
  },
  "lighting": {},
  "assets": [
    {
      "id": "flare-1",
      "path": "assets/<sha256>.png",
      "sha256": "...",
      "mediaType": "image/png",
      "bytes": 1234,
      "width": 1920,
      "height": 1080,
      "required": true
    }
  ],
  "futureLayers": []
}
```

导入分两阶段：

1. `inspect_linglight(path)`：只解压到 staging、校验、返回清单/警告/冲突，不修改正式数据。
2. `commit_linglight_import(token, strategy, parameter_only)`：`keep_both` 或 `overwrite_same_origin`，全部成功后原子替换预设 JSON。

`LingLightImportState` 作为 Tauri managed state 保存 `token → TempDir + inspection + source fingerprint + expires_at`：token 单次消费、10 分钟 TTL、最多 4 个 pending session；cancel/过期/应用退出释放 staging；重复 commit、过期 token 和并发 commit 必须拒绝。commit 在 preset mutex 内重新校验源指纹和冲突，不能完全信任 inspect 时的结果。

安全要求：

- 复用 `src-tauri/src/utils/archive/` 的 magic、ZIP Slip、压缩比、条目数与 staging 机制。
- `.linglight` 只接受 ZIP magic，不接受 7z。
- 校验真实 PNG magic、解码、尺寸、声明大小、SHA-256 与 manifest 一致。
- 公共 ZIP 层增加累计实际解压字节上限、`Read::take(remaining + 1)`、symlink/special-file 拒绝、重复 raw path/规范化冲突检测；不能只信 ZIP header 声明。
- 禁止脚本、绝对路径、`..`、盘符、UNC、符号链接和未声明必需文件。
- 必需素材缺失：拒绝。
- 可选 WebM/未来格式：允许用户明确选择“仅导入参数”；不得静默丢弃。
- 导出写临时文件，完成后原子 rename 到用户选择路径。
- “原子导入”的可见性提交点是预设 JSON：失败时旧 JSON 保持原值、既有共享 hash 绝不删除；崩溃最多留下未引用孤儿素材，不得留下引用缺失素材的可见预设。
- 新增跨平台 `atomic_replace_file`：临时文件必须与目标同目录，flush/fsync 后使用 Windows/Unix 对应替换语义；预设 Store、SceneStore 和导出共同复用。
- 批量导出定义为“用户选择目录后生成多个独立 `.linglight` 文件”，V1 不定义多预设单包。

## 8. 执行方式

### GitHub Issue / PR 门禁

- 本功能预计超过 2,000 行代码改动，已创建 GitHub Issue [#846](https://github.com/SlimeBoyOwO/LingChat/issues/846)，并以该 Issue 作为唯一状态跟踪入口。
- 行数口径：`origin/main...HEAD` 中源代码与配置文件的新增行 + 删除行；排除二进制、构建产物、自动生成文件、`pnpm-lock.yaml` 和纯文档。
- 达到或预计达到 2,000 行时，不允许直接创建 PR；必须先有开放 Issue。
- Issue 包含范围、排除项、19 个任务检查表、风险、测试状态和性能验收状态；每完成一个里程碑更新一次 Issue。
- 功能分支命名包含 Issue 编号；提交保持 Conventional Commits。
- PR 正文必须链接 Issue，并使用 `Closes #<issue>`；CI 全绿和 Issue 验收清单完成前不得合并。
- PR 创建后读取回 PR URL/编号并持续跟踪 checks；若失败，修复并重新验证，不把“PR 已创建”等同于“功能完成”。

推荐使用 subagent-driven-development：每个 Task 使用独立实现代理并执行对应专项测试，但不在每个 Task 后重复启动完整双重审查。

审查节奏固定为：

1. Task 1–9 完成后只做父代理的实际测试/构建验证并继续推进。
2. Task 10 完成后进行第一次集中审查：规格符合性 + 代码质量/安全。
3. 修复第一次集中审查发现的问题并完成 Task 11–19。
4. 全部 Task 完成后进行第二次、也是最终的集中审查：规格符合性 + 代码质量/安全。
5. 两次集中审查均通过后才允许创建/合并 PR。

每个实现 Task 完成后仍需：

1. 父代理复跑该 Task 的专项测试及必要构建。
2. 核对提交 SHA、工作区和计划范围。
3. 更新 Issue #846 的任务状态与真实测试结果。
4. 只有失败才立即回派修复；完整双重审查按上述两个里程碑执行。
5. 小步提交。

任何实现代理不得在没有先看到对应测试按预期失败的情况下编写生产代码。
